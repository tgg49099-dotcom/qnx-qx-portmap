3. EQUIVALENCE AVEC L'IMPLEMENTATION DE REFERENCE

La reference est la version du script au commit a2b42cc : elle cherche le
corpus ligne par ligne, sans filtre prealable, donc sans filtre de Bloom. Elle
a ete lancee sur le meme arbre, avec le meme corpus, le meme jour.

Les deux sorties sont identiques ligne pour ligne, a deux lignes pres :

  - la ligne "  date              : ..." (l'heure de l'execution) ;
  - la ligne "Duree du controle : ... s" (le temps mesure).

La commande de comparaison (elle ecarte ces deux lignes) :

    diff <(grep -v -e '^  date ' -e '^Duree du controle' sortie-corrigee.txt) \
         <(grep -v -e '^  date ' -e '^Duree du controle' sortie-reference.txt)

Sortie : vide (aucune difference).

Meme code de sortie (0) et meme verdict ("RESULTAT : 0 correspondance") des
deux cotes.

Pourquoi le verdict ne peut pas changer : un filtre de Bloom n'a aucun faux
negatif. Chaque morceau du corpus y est insere, donc une fenetre de 40
caracteres qui se trouve dans le corpus est toujours cherchee dans le texte
(la fenetre contient toujours un morceau entier du corpus, voir la constante
STEP = LINE_MIN - GRAM + 1). Un faux positif reste possible : il ne coute
qu'une recherche inutile dans le meme texte. Le controle peut donc seulement
devenir plus severe, jamais plus lenient.
